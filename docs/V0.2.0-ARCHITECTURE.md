# 125A GUI Designer v0.2.0 architecture

## Core rule

The GUI is not the source of truth. A `.125agui` project is the source of truth.

Both the human-facing Windows application and the automation/chat CLI read and write the same project model and call the same renderer.

## Beginner workflow

1. New asset
2. Choose asset type
3. Choose shape
4. Choose material
5. Choose lighting
6. Choose indicator/details
7. Choose output size/frames
8. Export for VSTGUI

The default interface must avoid technical terms such as azimuth, PBR, ambient occlusion, roughness, metalness and uidesc. Those belong in Expert Mode.

## First supported asset

Knob only. Other asset types are deferred until the knob workflow is complete and validated.

## Knob model

- shape: studio, flat, tapered, cylindrical, stepped
- material preset: plastic-black, metal-dark, aluminium, steel, brass, rubber
- lighting preset: soft, neutral, contrast, dramatic
- indicator: line, dot, notch, groove
- output: frame size, frame count, start/end angle, filmstrip layout

Expert parameters remain available in the project file and later in Expert Mode.

## Renderer strategy

The uploaded vstgui-edit source is MIT licensed (Copyright 2026 Roland Zwaga). We will preserve the MIT notice for reused substantial portions.

Useful upstream areas identified:

- src/domain/knobDesigner/geometry.ts
- src/domain/knobDesigner/materials.ts
- src/domain/knobDesigner/scene.ts
- src/domain/knobDesigner/filmstrip.ts
- src/domain/knobDesigner/validation.ts
- src/services/knobRenderer/
- src/components/KnobDesigner/

We will not expose the upstream UI unchanged. The 125A Simple Mode will be a new UX over a shared project/renderer layer.

## Windows delivery

Target: normal Windows desktop application, preferably Tauri if the final renderer/web stack proves compatible. The browser/web implementation remains an internal implementation detail for the user.

## Automation contract

The CLI must support, at minimum:

- validate project
- create project
- set one property
- apply named preset
- render/export asset
- batch variants

The first commit implements validation/edit/preset scaffolding. Rendering follows after the renderer adapter is integrated.
